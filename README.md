# Telegram-бот мониторинга ссылок

Бот принимает UTF-8 `.txt` с одной ссылкой на строку, сохраняет базу без автоматического
запуска, по команде проверяет ссылки параллельно, возвращает XLSX и круглосуточно
перепроверяет временно недоступные адреса.

## Интерфейс

- `Загрузка базы 📚` — запросить новый TXT-файл. Загрузка только сохраняет ссылки в Redis;
  проверка не запускается.
- `Начать поиск 🔍` — запустить первичную проверку или продолжить остановленный мониторинг.
- `Остановить` — остановить новые циклы. Результат уже выполняющегося цикла будет отброшен
  по номеру поколения.
- `/status` — состояние текущей базы; `/status <job_id>` — состояние конкретного задания.

Первый цикл проверяет все строки и присылает полный XLSX с листами `Сводка` и `Результаты`.
Таблица поддерживает фильтрацию, сортировку и кликабельные ссылки. Следующие циклы проверяют только
`broken`, `timeout` и `network_error`. Синтаксически некорректные и заблокированные безопасностью
адреса не повторяются: без изменения входной базы они не смогут восстановиться. Неизменившиеся
циклы проходят без сообщений; при восстановлении ссылок бот присылает новый отчёт.

## Запуск

1. Скопируйте `.env.example` в `.env` и укажите токен BotFather.
2. Запустите сервисы:

   ```bash
   docker compose up --build -d
   ```

3. Проверьте состояние:

   ```bash
   docker compose ps
   docker compose logs -f bot worker beat
   ```

Для перепроверки раз в 30 минут:

```env
RECHECK_INTERVAL_SECONDS=1800
```

Для перепроверки раз в минуту:

```env
RECHECK_INTERVAL_SECONDS=60
```

После изменения `.env` примените конфигурацию командой `docker compose up -d`.

## Архитектура

```text
Telegram -> aiogram bot -> Redis job/URL storage -> Celery worker
                                  ^                    |
                                  |                    v
                           Celery Beat <- due ZSET <- retry list
                                                       |
                                                       v
                                               asyncio + HTTPX
                                                       |
                                                       v
                                                XLSX -> Telegram
```

- Bot хранит базу и состояние в Redis, а в Celery передаёт только `job_id` и поколение.
- Один Celery task обрабатывает одну базу; HTTPX держит до 300 одновременных проверок.
- Celery Beat каждые 10 секунд выбирает из Redis задания, срок которых наступил.
- Redis-lock не допускает двух одновременных проверок одной базы.
- `Остановить` увеличивает поколение: поздний результат старого цикла игнорируется.
- Активное задание обновляет TTL на каждом цикле, поэтому остаётся в Redis неограниченно долго,
  пока мониторинг работает. После остановки данные удаляются по TTL, по умолчанию через сутки.
- Redis использует AOF; контейнеры настроены с `restart: unless-stopped`.
- Должен работать ровно один экземпляр Celery Beat, иначе возможна двойная диспетчеризация.

## Производительность

Приём и постановка 1 000 ссылок в очередь укладываются примерно в 1–2 секунды. Полная проверка
произвольных сайтов не может иметь такой гарантии из-за DNS, TCP/TLS, удалённых серверов и
тайм-аутов. Дубликаты запрашиваются один раз, но сохраняются отдельными строками XLSX.

Начинайте с `CHECK_CONCURRENCY=300`. Слишком большое значение может исчерпать сокеты, перегрузить
DNS или вызвать rate limit. Тайм-аут одной ссылки по умолчанию — 5 секунд.

## Безопасность

Перед каждым запросом и перенаправлением блокируются loopback, private, link-local и другие
непубличные адреса. Для публичного развёртывания дополнительно запретите доступ к внутренним сетям
на уровне firewall или egress proxy: DNS может измениться между проверкой и подключением.
