# Telegram-бот для мониторинга ссылок

Бот принимает TXT-файл со списком URL, проверяет доступность ссылок и отправляет Excel-отчёт. После первой проверки он продолжает периодически перепроверять только временно недоступные адреса и уведомляет, если их состояние изменилось.

## Возможности

- Загрузка UTF-8 TXT-файла: одна ссылка в каждой строке.
- Параллельная проверка ссылок с поддержкой редиректов.
- XLSX-отчёт с листами «Сводка» и «Результаты», фильтрами, сортировкой и кликабельными URL.
- Повторная проверка `broken`, `timeout` и `network_error` по расписанию.
- Хранение заданий и результатов в Redis.
- Защита от запросов к локальным, приватным и другим непубличным IP-адресам.

## Как пользоваться ботом

1. Нажмите **«Загрузка базы 📚»** и отправьте TXT-файл со ссылками.
2. Нажмите **«Начать поиск 🔍»**. Бот выполнит первичную проверку и пришлёт XLSX-файл.
3. Используйте **«Остановить»**, чтобы прекратить мониторинг. Результат уже выполняющегося цикла не будет отправлен.
4. Команда `/status` показывает состояние текущей базы, а `/status <job_id>` — состояние конкретного задания.

Ссылки с ошибочным форматом или заблокированные защитой не перепроверяются: для них нужно исправить исходный файл и загрузить базу заново. Если очередная проверка не обнаружила изменений, бот не отправляет лишних сообщений.

## Быстрый запуск

### Требования

- Docker и Docker Compose;
- токен Telegram-бота, полученный у [BotFather](https://t.me/BotFather).

### Настройка и запуск

1. Скопируйте пример конфигурации:

   ```bash
   cp .env.example .env
   ```

   В Windows PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

2. Откройте `.env` и укажите настоящий токен:

   ```env
   BOT_TOKEN=123456789:ваш-токен-от-BotFather
   ```

3. Соберите и запустите сервисы:

   ```bash
   docker compose up --build -d
   ```

4. Убедитесь, что контейнеры запущены, и при необходимости посмотрите логи:

   ```bash
   docker compose ps
   docker compose logs -f bot worker beat
   ```

После изменения `.env` примените новую конфигурацию:

```bash
docker compose up -d
```

## Основные настройки

Все параметры задаются в `.env`.

| Параметр | По умолчанию | Назначение |
| --- | ---: | --- |
| `CHECK_CONCURRENCY` | `300` | Число одновременных проверок. |
| `CHECK_CONNECT_TIMEOUT_SECONDS` | `2.0` | Тайм-аут подключения. |
| `CHECK_READ_TIMEOUT_SECONDS` | `3.0` | Тайм-аут чтения ответа. |
| `CHECK_TOTAL_TIMEOUT_SECONDS` | `5.0` | Общий тайм-аут одной ссылки. |
| `CHECK_RETRIES` | `0` | Число повторов одной проверки. |
| `CHECK_MAX_REDIRECTS` | `5` | Максимальное число редиректов. |
| `MAX_FILE_BYTES` | `2097152` | Максимальный размер TXT-файла (2 МБ). |
| `MAX_URLS_PER_FILE` | `10000` | Максимальное число ссылок в файле. |
| `RECHECK_INTERVAL_SECONDS` | `1800` | Интервал повторной проверки временных ошибок. |
| `JOB_TTL_SECONDS` | `86400` | Срок хранения остановленного задания в Redis. |

Для начала рекомендуется оставить `CHECK_CONCURRENCY=300`. Увеличение значения не всегда ускоряет работу: оно может исчерпать сокеты, создать нагрузку на DNS или вызвать ограничение частоты запросов со стороны сайтов.

Например, для проверки проблемных ссылок раз в минуту добавьте в `.env`:

```env
RECHECK_INTERVAL_SECONDS=60
```

## Как это устроено

```text
Telegram → aiogram bot → Redis (задания и URL) → Celery worker
                            ↑                       │
                            │                       ↓
                     Celery Beat ← планировщик ← asyncio + HTTPX
                                                    │
                                                    ↓
                                             XLSX → Telegram
```

- Bot сохраняет базу и состояние задания в Redis; в Celery передаёт только идентификатор задания.
- Один worker обрабатывает одну базу, а HTTPX выполняет проверки параллельно.
- Celery Beat раз в 10 секунд выбирает из Redis задания, срок следующей проверки которых наступил.
- Redis-lock предотвращает одновременную проверку одной базы двумя задачами.
- Активные задания продлевают TTL при каждом цикле. После остановки данные удаляются по TTL.
- Redis использует AOF, а сервисы Docker перезапускаются с `restart: unless-stopped`.

Важно: должен работать только один экземпляр Celery Beat, иначе задания могут запускаться дважды.

## Безопасность

Перед каждым запросом и редиректом бот блокирует loopback-, private-, link-local- и другие непубличные адреса. При публичном развёртывании дополнительно ограничьте доступ к внутренним сетям с помощью firewall или egress proxy: DNS-запись может измениться между проверкой адреса и подключением.
